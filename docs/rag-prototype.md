# QuadCoach Behavioral Coaching RAG Prototype

## Architecture

```text
Original Markdown coaching notes
    -> section-aware chunking
    -> FastEmbed all-MiniLM-L6-v2 embeddings
    -> local JSON vector index (ignored by Git)

User answer -> query embedding -> cosine top-3 chunks
    -> existing Anthropic integration as behavioral coach
    -> feedback and source titles/sections in the Practice view
```

## Ingestion and storage

The small corpus is in `knowledge/`. Each document has a title and level-two
sections. The ingestion script treats each section as its own chunk, combining
paragraphs up to 1,200 characters and splitting longer paragraphs at that
limit. Every chunk stores a stable ID, title, filename, section, text, and
embedding.

FastEmbed uses the CPU-friendly `sentence-transformers/all-MiniLM-L6-v2`
model. The first ingestion run downloads the model. The resulting local JSON
index is written to `backend/data/coaching_index.json` and is intentionally
gitignored. Re-run ingestion whenever the Markdown corpus changes.

From the repository root, with the backend virtual environment active:

```powershell
python -m pip install -r backend/requirements.txt
Set-Location backend
python -m scripts.ingest_coaching_knowledge
```

## Retrieval and feedback

`retrieve_relevant_chunks(query, top_k=3)` embeds the query and ranks all
indexed chunks with cosine similarity. It returns text, score, chunk ID, and
source metadata. The authenticated `POST /api/feedback/behavioral` endpoint
uses the user's answer as the query, retrieves three chunks, and passes them
to the existing Anthropic client as reference material, clearly separated
from the answer. The prompt treats both as untrusted data and prohibits
unsupported source claims. The API's source list is derived directly from the
retrieved chunks, not generated by the model.

Open **Practice** in the signed-in QuadCoach sidebar, submit a behavioral
answer, and review the coaching notes cited below the feedback.

## Retrieval evaluation

Run the reproducible eight-query evaluation after ingestion:

```powershell
Set-Location backend
python -m scripts.evaluate_coaching_retrieval
```

The evaluator prints each query, top-three chunk IDs, source sections and
cosine scores, the expected source, and whether that source appeared in the
top three. Recall@3 is the number of queries whose expected source appeared in
the top three divided by eight.

**Measured Recall@3:** 8/8 queries = **100%** on the current hand-written
evaluation set. The set is small and authored alongside the corpus, so this
is a smoke-test baseline, not an independent measure of general retrieval
quality. The query about choosing a database ranked a technical-challenge
chunk first but still included the expected Project Tradeoffs source in its
top three.

## Tests

From the repository root:

```powershell
Set-Location backend
python -m unittest discover -s tests -v
```

The unit tests use a deterministic fake embedder to check chunk metadata,
ranking flow, missing-index errors, and invalid inputs without requiring a
model download.

## Limitations and next improvements

- The corpus is four short, hand-written documents; retrieval scores and
  Recall@3 are only a tiny prototype evaluation, not evidence of production
  quality.
- The JSON index is local to one checkout and loads the full corpus for each
  retrieval. It is not a multi-user or production vector store.
- Similarity scores are ranking signals, not calibrated confidence.
- The practice view uses one fixed behavioral prompt. It does not yet use a
  saved resume profile, target job description, conversation history, or
  persistent feedback reports.
- The model-generated coaching response is not independently graded for
  factual accuracy; returned citations identify retrieved context, not proof
  that every feedback sentence is entailed by it.

Potential next steps: add retrieval-quality cases based on student wording,
persist and use a reviewed candidate profile, and evaluate coaching quality
with human-reviewed sample answers before expanding the corpus or storage.
